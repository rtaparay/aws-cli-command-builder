# Deploying to Vercel

The app is a static site generated by Vite. Vercel builds it and serves it from its CDN, with no server of your own.

## 1. Project configuration

The repository already includes `vercel.json`:

| Setting | Value | Where |
|---|---|---|
| Framework | `vite` | `vercel.json` |
| Build command | `npm run build` | `vercel.json` |
| Install command | `npm install` | `vercel.json` |
| Output folder | `dist` | `vercel.json` |
| Clean URLs | enabled (`cleanUrls`) | `vercel.json` |
| `catalog.json` caching | `public, max-age=3600, stale-while-revalidate=86400` | `vercel.json` |
| Node version | 26 | `.nvmrc` and `engines` in `package.json` |

Nothing needs to be configured manually in the Vercel dashboard.

## 2. First deployment

### Option A: from the web dashboard (recommended)

1. Push the repository to GitHub, GitLab, or Bitbucket.
2. On [vercel.com](https://vercel.com), click **Add New → Project** and import the repository.
3. Vercel detects Vite. Check that the fields match the table above and click **Deploy**.
4. When it finishes, you get a URL like `https://<project>.vercel.app`.

### Option B: from the CLI

```bash
npm install -g vercel
cd aws-cli-command-builder
vercel login
vercel              # first deployment (preview)
vercel --prod       # production deployment
```

The CLI asks you to confirm the project and settings the first time and stores the link in `.vercel/`. That folder should not be versioned; add it to `.gitignore` if Vercel did not do it already.

## 3. Continuous deployments

If the project is connected to Git:

| Event | Result |
|---|---|
| Push to the production branch (usually `main`) | **Production** deployment. |
| Push to another branch or a Pull Request | **Preview** with its own URL. |

Each deployment is immutable. You can return to a previous version from **Deployments → ⋯ → Promote to Production** (or *Rollback*).

## 4. Custom domain

1. In the project, go to **Settings → Domains** and add your domain.
2. Configure DNS as Vercel indicates (an `A` or `CNAME` record).
3. Vercel issues the HTTPS certificate automatically.

## 5. Verification after deploying

Check the following on the published URL:

- [ ] The page loads and shows the list of services (not just the handful from the sample). If you only see a few, `catalog.json` is not loading; check the browser's **Network** tab.
- [ ] `https://<your-url>/catalog.json` returns `200` and JSON.
- [ ] The `Cache-Control` header of `catalog.json` matches `vercel.json`.
- [ ] Reloading any URL does not produce a 404 (the app uses no routes, but the host must serve `index.html`).
- [ ] The light/dark theme and the copy button work.

## 6. Specific considerations

- **Catalog size:** `catalog.json` is ~23 MB. Vercel compresses it in transit, but the first load can be slow on slow connections. Later loads come from the browser cache.
- **Limits:** the free Vercel plan comfortably covers a static site like this. Bandwidth and build limits are in Vercel's documentation; review them if traffic grows.
- **AI keys:** keys that users enter in the assistant are stored in their browser. **Do not** configure provider keys as Vercel environment variables: the code would read them from the public bundle.
- **Environment variables:** the app needs none.

## 7. Common problems

| Symptom | Likely cause | Solution |
|---|---|---|
| Build error "command not found" | Different Node version | Vercel uses the version from `.nvmrc` / `engines`. Confirm the project does not force another version in **Settings → Node.js Version**. |
| Page loads but without the full catalog | `public/catalog.json` was not pushed to the repository, or `.gitignore` excludes it | Check with `git ls-files public/catalog.json`. |
| Slow or rejected deployment due to size | Large artifacts | `dist/` contains `catalog.json` (~23 MB). If the limit affects you, consider compressing it or splitting it per service (see the README, improvements section). |
| Changes not visible after deploying | Browser cache of `catalog.json` (1 h) | Force reload (Ctrl+F5) or wait. |

## 8. Deploying from local without Git

```bash
npm ci
npm run build
npx vercel deploy dist --prod
```

Uploading `dist/` directly works, but then `vercel.json` is not applied (including `cleanUrls` and caching). For a production-equivalent deployment, deploying from the project root with `vercel --prod` is recommended.
